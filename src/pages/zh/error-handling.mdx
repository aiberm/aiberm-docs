# 错误处理

调用 Aiberm API 失败时，接口会返回一个 JSON 错误对象。你可以根据 HTTP 状态码、`error.code` 和 `error.message` 快速判断问题类型。

如需人工支持，请把完整错误信息里的所有 `request id` 一并提供给我们。

## 错误响应格式

```json
{
  "error": {
    "message": "用户额度不足, 剩余额度: ¥0.00 (request id: 20260622xxxxxxxx)",
    "type": "new_api_error",
    "code": "insufficient_user_quota"
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `message` | 错误说明。末尾的 `(request id: ...)` 是本次请求的追踪号，联系客服时请提供。 |
| `code` | 错误类别标识，可对照下方常见错误表。 |
| `type` | 错误来源标记，一般无需特别处理。 |

> 如果 `message` 末尾出现多个 `(request id: ...)`，这是正常现象，表示请求经过了多层服务。联系客服时复制整段错误信息即可，无需手动删减。

## 按 HTTP 状态码定位

| 状态码 | 含义 | 处理建议 |
| --- | --- | --- |
| `400` | 请求格式有误 | 检查请求体 JSON、必填参数、`Content-Type` 和模型名。 |
| `401` | 密钥无效 | 检查 API Key 是否正确、过期、禁用或额度耗尽。 |
| `403` | 没有权限或余额不足 | 检查账户余额、密钥权限、模型权限和来源 IP。 |
| `404` | 资源不存在 | 检查接口地址和模型名是否拼写正确。 |
| `429` | 请求太频繁 | 降低并发或请求频率，稍后重试。 |
| `500` | 服务端内部错误 | 稍后重试；若持续出现，请带上 `request id` 联系客服。 |
| `503` | 暂时无可用服务 | 该模型暂时无可用线路，稍后重试或联系客服。 |

## 密钥与登录错误

这类错误通常返回 `401`。

| 你会看到的提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| `无效的令牌` | API Key 错误或不存在。 | 核对 Key 是否完整，确认没有多复制或少复制字符，建议从控制台重新复制。 |
| `该令牌已过期` | 密钥已超过有效期。 | 在控制台重新生成密钥，或延长该密钥有效期。 |
| `该令牌额度已用尽` | 该密钥单独设置的额度已用完。 | 提升该密钥额度，或改用额度充足的密钥。 |
| `该令牌状态不可用` | 密钥被禁用。 | 在控制台启用该密钥，或新建一个密钥。 |
| `未提供令牌` | 请求没有携带 API Key。 | 在请求头中加入 `Authorization: Bearer sk-xxxxxx`。 |

## 权限与余额错误

这类错误通常返回 `403`。

| 你会看到的提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| `用户额度不足, 剩余额度: ...` | 账户余额不够本次调用。 | 充值后重试。 |
| `预扣费额度失败, 用户剩余额度: ...` | 余额不足以覆盖本次预估费用。 | 充值后重试，或减少 `max_tokens`、缩短输入内容。 |
| `您的 IP 不在令牌允许访问的列表中` | 该密钥绑定了 IP 白名单，当前 IP 不在允许列表内。 | 使用允许的 IP 访问，或在控制台调整白名单。 |
| `用户已被封禁` | 账号被停用。 | 联系客服了解原因。 |
| `无权访问 xxx 分组` | 该密钥无权使用对应分组。 | 改用有权限的分组，或申请开通。 |
| `该令牌无权访问模型 xxx` | 该密钥的可用模型范围不包含当前模型。 | 换用允许的模型，或在控制台放开该密钥的模型范围。 |

## 请求内容错误

这类错误通常返回 `400`。

| 你会看到的提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| `Invalid request, ...` | 请求体无法解析。 | 检查 JSON 是否合法，确认 `Content-Type` 为 `application/json`。 |
| `未指定模型名称，模型名称不能为空` | 请求缺少 `model` 字段。 | 在请求体中补上正确的 `model`。 |
| `检测到敏感词` 类提示 | 输入内容命中内容安全规则。 | 调整输入内容后重试。 |

## 请求频率错误

这类错误通常返回 `429`。

| 你会看到的提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| `您已达到请求数限制：N分钟内最多请求M次` | 触发成功请求数上限。 | 降低请求频率，等待限制窗口结束后重试。 |
| `您已达到总请求数限制：...，包括失败次数...` | 包含失败请求在内的总请求数超限。 | 先排查是否有大量失败请求在重复空转，修正后再重试。 |

## 模型与线路错误

这类错误通常返回 `404` 或 `503`。

| 你会看到的提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| `模型不存在` | 模型名写错，或该模型未开放给当前密钥。 | 确认模型名拼写和密钥模型权限。 |
| `无可用渠道` | 该模型当前没有可用线路。 | 稍后重试；若持续不可用，请联系客服。 |

## 服务端错误

这类错误通常返回 `500` 或 `503`。

| 你会看到的提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| 各类内部错误提示 | 服务端临时异常，或上游服务暂时不可用。 | 稍后重试；若持续发生，请带上 `request id` 联系客服。 |

## 联系客服前请准备

为了更快定位问题，请提供：

1. 完整错误信息，包括 `message`、`code` 和所有 `request id`。
2. 大致发生时间。
3. 调用的模型名与接口地址。
4. 使用的密钥前几位，例如 `sk-abcd...`。不要提供完整密钥。
