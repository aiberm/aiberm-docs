# Настройка Magpie

В этом руководстве показано, как добавить [Aiberm](https://aiberm.com) как провайдера в [magpie](https://usemagpie.ai/). Достаточно добавить его один раз, и Claude Code, Codex, Gemini CLI, OpenCode и другие агенты, которые поддерживает magpie, смогут выбирать модели Aiberm.

magpie — шлюз с открытым исходным кодом, который работает на вашем компьютере (по умолчанию на `127.0.0.1:3425`). Он поддерживает API OpenAI, Anthropic и Gemini и переводит запросы между ними, включая стриминг и вызовы инструментов. Агенты общаются только с magpie. Ваш API-ключ Aiberm хранится в magpie, а в конфигурационные файлы агентов вместо него записываются адрес локального шлюза и локальный токен.

<Callout client:load type="info">
Эта страница основана на документации magpie [Get started](https://usemagpie.ai/docs/start) и [Add to magpie](https://usemagpie.ai/docs/import) и проверена на magpie 0.1.1276. magpie быстро меняется; если приложение и эта страница расходятся, ориентируйтесь на документацию magpie.

## Предварительные требования

- Аккаунт Aiberm ([зарегистрироваться](https://aiberm.com/register))
- API-ключ Aiberm ([создать](https://aiberm.com/console/token))
- magpie 0.1.8 или новее (нужен для ссылок импорта)

Загрузки для macOS, Windows и Linux доступны на [странице загрузки](https://usemagpie.ai/#get). На macOS или Linux можно также установить magpie из терминала:

```bash
curl -fsSL https://usemagpie.ai/install.sh | sh
```

В Linux скрипт устанавливает десктопное приложение, если есть GTK 3 и WebKitGTK 4.1, а иначе — терминальную версию. Если загрузка не может достучаться до GitHub, укажите прокси: `curl -fsSL https://usemagpie.ai/install.sh | sh -s -- --proxy http://127.0.0.1:7890`.

## Эндпоинты Aiberm

| Протокол | Значение в magpie | Примечания |
| --- | --- | --- |
| OpenAI Chat | `https://aiberm.com/v1` | Должен заканчиваться на `/v1`. magpie добавляет `/chat/completions`. |
| Anthropic Messages | `https://aiberm.com` | Корневой адрес, без `/v1`. То же значение, что и `ANTHROPIC_BASE_URL` в руководстве [Настройка Claude Code](/docs/ru/claude-code/). |
| OpenAI Responses | Оставьте пустым | См. ниже. |
| Gemini | Оставьте пустым | См. ниже. |

Заполните и Chat URL, и Anthropic URL. Запросы Claude Code идут на Anthropic URL без изменений, и туда же magpie отправляет запросы к моделям Claude от других агентов. Остальные запросы идут на Chat URL — с переводом, если агент использует другой API. Aiberm принимает оба протокола для своих чат-моделей.

Оставьте Responses URL и Gemini URL пустыми. Эндпоинты Responses (`/v1/responses`) и Gemini (`/v1beta`) у Aiberm обслуживают не все модели: например, модели Claude через них недоступны. Без этих URL magpie сам переводит Responses-запросы Codex и запросы Gemini CLI, поэтому Codex и Gemini CLI могут использовать любую модель Aiberm.

<Callout client:load type="tip">
Если в Codex вы используете только модели GPT, руководство [Настройка Codex CLI](/docs/ru/codex/) подключает Codex к Responses API Aiberm напрямую, без перевода.
</Callout>

## Способ 1: ссылка импорта (рекомендуется)

На компьютере, где установлен magpie, откройте ссылку ниже. magpie покажет окно подтверждения с именем провайдера, его эндпоинтами и полем для API-ключа и предупредит, на какие хосты будут отправляться ваши промпты и ключ. **Пока вы не нажмёте Add, ничего не сохраняется.**

[Add to magpie](https://usemagpie.ai/import#name=Aiberm&id=aiberm&chat=https%3A%2F%2Faiberm.com%2Fv1&anthropic=https%3A%2F%2Faiberm.com&website=https%3A%2F%2Faiberm.com&keys=https%3A%2F%2Faiberm.com%2Fconsole%2Ftoken)

Ссылка намеренно не содержит API-ключа. На публичной странице никогда не должно быть секретов; вставьте свой ключ в окне. Ключ хранится только в `~/.config/magpie/providers.json` на вашем компьютере, и прочитать его может только ваш пользователь. Параметры веб-ссылки идут после `#`, а эту часть браузеры никогда не отправляют на сервер.

Если графической среды нет (например, при работе по SSH), передайте те же параметры терминальной версии. Она покажет ту же сводку и спросит подтверждение перед добавлением:

```bash
magpie import 'magpie://import?name=Aiberm&id=aiberm&chat=https%3A%2F%2Faiberm.com%2Fv1&anthropic=https%3A%2F%2Faiberm.com&website=https%3A%2F%2Faiberm.com&keys=https%3A%2F%2Faiberm.com%2Fconsole%2Ftoken'
```

## Способ 2: добавление в приложении

1. Откройте magpie, перейдите в **Providers** и нажмите **＋ Add provider**.
2. Выберите **Custom** (любой совместимый URL). Готового пресета для Aiberm в magpie нет.
3. Заполните форму:

| Поле | Значение |
| --- | --- |
| Name | `Aiberm`. magpie выводит из него ID `aiberm`, поэтому агенты видят модели как `aiberm/<model>`. |
| Base URL | `https://aiberm.com/v1`, в поле API выбрано **OpenAI compatible** |
| API key | Ваш API-ключ Aiberm |
| More endpoints → Anthropic URL | `https://aiberm.com` |
| More endpoints → Responses URL, Gemini URL | Оставьте пустыми. Если **Detect APIs** их заполнит, очистите. |
| Models | Оставьте пустым |

4. Сохраните. magpie запросит `https://aiberm.com/v1/models` и предложит полученные модели в списке выбора каждого агента. Перед сохранением через **Fetch models** можно выбрать, какие модели увидят агенты, а **Test models** проверяет ключ и URL.

Если поле Models пустое, список берётся из `/v1/models`, поэтому модели, которые Aiberm добавит позже, появятся, когда вы снова загрузите модели (или выполните `magpie provider refresh aiberm`). В список входят все модели, доступные вашему ключу, в том числе модели для изображений, речи и эмбеддингов, которые агенты для программирования использовать не могут; выбирайте только нужные. Задавайте список через запятую, только если автоматический список неверен. ID моделей указаны на [странице цен](https://aiberm.com/pricing) и в разделе [Список моделей](/docs/ru/models/), например `claude-sonnet-5-5`, `gpt-5.6-sol` или `google/gemini-3.1-pro`.

## Выбор модели для каждого агента

Откройте **Agents**. Каждая строка — агент, установленный или настроенный на этом компьютере. Нажмите на модель и выберите нужную в группе **aiberm** или введите `aiberm/` и ID модели.

```bash
magpie claude aiberm/claude-sonnet-5-5
magpie codex aiberm/gpt-5.6-sol
magpie opencode aiberm/claude-sonnet-5-5
magpie gemini aiberm/google/gemini-3.1-pro
```

magpie меняет только те ключи конфигурации, за которые отвечает. Комментарии, порядок и отступы в конфигурации агента остаются как есть. Уже запущенный сеанс сохраняет модель, с которой стартовал. **Начните новый сеанс**, чтобы изменение вступило в силу. Для Codex также перезапустите приложение Codex: список моделей оно формирует при запуске.

| Агент | Что записывает magpie |
| --- | --- |
| Claude Code | В блок `env` файла `~/.claude/settings.json`: `ANTHROPIC_BASE_URL` (локальный шлюз, а не Aiberm), `ANTHROPIC_AUTH_TOKEN` (локальный токен, а не ваш ключ Aiberm) и переменные модели. |
| Codex | В `~/.codex/config.toml`: адрес шлюза и модель, а также список моделей в `magpie-models.json`. Ваш вход в ChatGPT не затрагивается. |
| OpenCode, Pi, Crush | Запись провайдера с именем `magpie`, в которой модель задана как `magpie/aiberm/<model>`. |
| Gemini CLI | В `~/.gemini/.env`: `GOOGLE_GEMINI_BASE_URL`, указывающий на шлюз, и локальный API-ключ; выбрана аутентификация по API-ключу. Ваш вход через Google сохраняется. |

Чтобы вернуть всё обратно, выберите одну из собственных моделей агента или выполните `magpie claude default` (замените `claude` на имя агента). magpie удалит то, что записал, и восстановит значения, которые заменил.

### Если агент уже подключён к Aiberm напрямую

Экспортировать `ANTHROPIC_BASE_URL` или `OPENAI_BASE_URL` для magpie не нужно: он сам записывает адрес шлюза в конфигурацию каждого агента.

- **Claude Code или Codex настроен в своём конфигурационном файле** (как в руководствах [Настройка Claude Code](/docs/ru/claude-code/) и [Настройка Codex CLI](/docs/ru/codex/)): ничего делать не нужно. magpie заменяет только нужные ему значения, а `magpie <agent> default` возвращает ваши.
- **Claude Code настроен через `export`, `setx` или пользовательские переменные среды Windows**: их можно оставить. Claude Code отдаёт приоритет значениям из `~/.claude/settings.json`, поэтому, пока вы пользуетесь magpie, действуют его настройки. После `magpie claude default` Claude Code вернётся к вашим переменным и будет обращаться к Aiberm напрямую.

## Во время работы

- **magpie должен быть запущен.** Если закрыть окно, он останется в строке меню или в системном трее. `magpie tray` запускает только значок, а `magpie serve` — только шлюз. Чтобы magpie запускался при входе в систему без окна, выполните `magpie daemon install` на macOS или Linux либо `magpie autostart on` на Windows.
- Добавляйте ключ только в magpie. magpie не читает API-ключи из переменных окружения оболочки.
- Прокси-приложение (Clash, Surge, mihomo и подобные инструменты с включённым системным прокси, TUN или расширенным режимом) может перехватывать трафик к `127.0.0.1:3425`. Если агент возвращает 502, а запрос так и не появляется на вкладке **Routing** в magpie, добавьте правила, которые направляют локальные адреса напрямую, и поставьте их перед остальными правилами:

  ```text
  IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
  IP-CIDR6,::1/128,DIRECT,no-resolve
  ```

  В конфигурации Clash или mihomo поместите те же строки под `rules:`, каждую с префиксом `- `.
- Вкладка **Usage** учитывает только вызовы, прошедшие через шлюз. Вызовы, которые агент делает напрямую в Aiberm, туда не попадают. Если вы не задали собственные цены или ценовой коэффициент для провайдера, magpie оценивает стоимость по прейскурантным ценам производителей моделей, а они могут быть значительно выше того, что списывает Aiberm. Фактические списания смотрите в [консоли Aiberm](https://aiberm.com/console).

## Необязательно: несколько ключей или резервный вариант

Все API-ключи одного аккаунта Aiberm расходуют один и тот же баланс. Когда баланс заканчивается, все ключи этого аккаунта перестают работать одновременно, поэтому дополнительные ключи того же аккаунта не служат резервом на случай, когда закончились средства. Несколько ключей полезны, если они от разных аккаунтов Aiberm или если у ключа в консоли задан собственный лимит квоты и вы хотите, чтобы после его исчерпания работу подхватывал следующий ключ.

Чтобы использовать несколько ключей, вставьте их в поле API key провайдера Aiberm через запятую, пробел или с новой строки. Первым пробуется первый ключ. Затем выберите, как распределять запросы:

| Routing | Поведение с ключами Aiberm |
| --- | --- |
| Smart (по умолчанию) | У ключей нет лимита подписки, который можно было бы сравнить, поэтому они пробуются в том порядке, в каком вы их ввели. Ключ, вернувший ошибку, на время выбывает, и отвечает следующий. |
| In order | Использует первый ключ, пока он не вернёт ошибку, не исчерпает квоту или не упрётся в лимит запросов, затем переходит к следующему. |
| In turn | Каждый ход диалога уходит на следующий ключ, распределяя нагрузку. |
| By weight | Распределяет запросы по весу, который вы задаёте рядом с каждым ключом. |

magpie переключается на следующий ключ при ошибках вроде 401, 403, 429 и 5xx, если агенту ещё ничего не отправлено. Least used first и Weekly pace рассчитаны в основном на подписки; для ключей они лишь сравнивают недавний расход токенов. Все режимы, кроме Smart, предоставляет встроенный плагин magpie **rotation**; если доступен только Smart, включите этот плагин.

Более распространённая схема — резервирование между провайдерами: сначала подписка, а когда она закончится — Aiberm. На вкладке **Routing** создайте группу, где первой идёт модель из вашей подписки, а второй — модель Aiberm, например модель из плана Claude, а за ней `aiberm/claude-sonnet-5-5`, и укажите агенту `group/<id>`. Когда у первого участника закончилась квота, сработал лимит запросов или он недоступен, magpie отправляет ход следующему участнику до того, как ошибка дойдёт до агента. Кроме того, magpie сам создаёт `group/auto-<model>`, когда два ваших провайдера предоставляют одну и ту же модель.

## Восстановление и устранение неполадок

| Что вы видите | Что делать |
| --- | --- |
| Окно подтверждения не открывается | Проверьте, что magpie установлен и его версия 0.1.8 или новее. Если он не установлен, веб-ссылка сначала предложит его скачать. В остальных случаях добавьте провайдера вручную. |
| Список моделей пуст | Откройте провайдера Aiberm и запустите **Test models**. Убедитесь, что ключ действителен, а Base URL равен `https://aiberm.com/v1`, затем снова загрузите модели. |
| Агент по-прежнему использует старую модель | Завершите текущий сеанс и начните новый. Также перезапустите приложение Codex. |
| 401 | Ключ неверен, удалён или истёк либо исчерпан его собственный лимит квоты. Проверьте его в разделе [API Tokens](https://aiberm.com/console/token): продлите срок действия, увеличьте лимит или создайте новый ключ и замените его в magpie. Не редактируйте токен в конфигурации агента. |
| 403 | Чаще всего на балансе аккаунта недостаточно средств: [пополните счёт](https://aiberm.com/console/topup) и повторите запрос. Новый ключ не поможет. В остальных случаях ключу не разрешено вызывать эту модель или его белый список IP не включает этот компьютер; проверьте настройки ключа. |
| 503 с `model_not_found` | ID модели неверен или у модели сейчас нет доступного маршрута. Проверьте ID на [странице цен](https://aiberm.com/pricing) или выберите другую модель. |
| Нужно удалить Aiberm | Сначала выполните `magpie <agent> default` для каждого агента, который использует модель `aiberm/`, затем удалите Aiberm в **Providers**. Если сначала удалить провайдера, magpie переключит этих агентов на одноимённую модель другого провайдера или вернёт им модель по умолчанию. |

Другие коды ошибок описаны в разделе [Обработка ошибок](/docs/ru/error-handling/). Документация самого magpie — в разделах [Get started](https://usemagpie.ai/docs/start) и [Add to magpie](https://usemagpie.ai/docs/import).
