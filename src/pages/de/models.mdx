# Modellliste

Ruft eine Liste aller KI-Modelle ab, auf die der aktuelle Benutzer zugreifen kann, einschließlich Modell-IDs, Namen, Anbietern und detaillierten Informationen.

<Callout client:load type="info" title="Zur Modellliste und Token-Gruppen">
Die in der Liste zurückgegebenen Modelle hängen von der Token-Gruppe ab, zu der Ihr API KEY gehört. Die Token-Gruppe können Sie beim Erstellen oder Bearbeiten von Tokens unter Konsole → API Tokens auswählen.
</Callout>

## Endpunkt

`GET https://aiberm.com/v1/models`

## Antwortfelder

**Felder auf oberster Ebene:**
- `success` – Boolean, gibt an, ob die Anfrage erfolgreich war
- `data` – Array von Modellobjekten (nur bei Erfolg zurückgegeben)
- `message` – Fehlermeldung (nur bei Fehler zurückgegeben)

**Felder des Modellobjekts:**
- `id` – Eindeutiger Bezeichner des Modells
- `object` – Objekttyp, fest als "model"
- `created` – Zeitstempel der Modellerstellung
- `owned_by` – Modellanbieter (z. B. openai, anthropic)
- `supported_endpoint_types` – Array der unterstützten API-Endpunkttypen

## Unterstützte Endpunkttypen

- `chat` – Chat Completion
- `completion` – Text Completion
- `embedding` – Text Embedding
- `image` – Bildgenerierung
- `audio` – Audioverarbeitung
- `rerank` – Rerank

## Wichtige Hinweise

<Callout client:load type="info" title="Authentifizierung erforderlich">
Es muss ein gültiges API-Token angegeben werden. Das Token bestimmt, auf welche Modelle der Benutzer zugreifen kann.
</Callout>

<Callout client:load type="info" title="Berechtigungssteuerung">
Die zurückgegebene Modellliste wird anhand von Benutzer- und Token-Gruppen gefiltert und zeigt nur Modelle, auf die der Benutzer zugreifen darf.
</Callout>

## Häufige Fehler

- `401 Unauthorized` – API-Token ist ungültig oder abgelaufen
- `403 Forbidden` – Der Benutzer hat keine Zugriffsberechtigung
- `500 Internal Server Error` – Interner Serverfehler
